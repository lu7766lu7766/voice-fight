# 聲控對戰 Voice Fight

兩支手機連到同一台電腦，各自挑一位 Q 版俠客，找出文字方塊中相連的招式名稱、**對著麥克風念出來**來出招。

- 電腦是伺服器，首頁只顯示**房間號碼**和 **QR Code**
- 一個房間最多兩人：**先進房的在左方、後進房的在右方**
- 手機畫面上半部是對戰場景，下半部是像 Candy Crush 一樣的文字方塊
- 出招時兩支手機會同步播放施招動畫、受擊動畫，並同步消除方塊，畫面保持一致

## 快速開始

```bash
npm install
npm start
```

1. 電腦瀏覽器開啟 **http://localhost:3000**，畫面會顯示房間號碼和 QR Code。
2. 兩支手機掃描 QR Code 進入房間。點角色可以先看能力和招式，按「**確定選擇**」才送出；確定後再點別的角色會取消確定。**兩人都確定**才會開始倒數。右上角有「離開房間」。
3. 雙方都確定後**自動倒數 10 秒**，這段時間可以打開**招式表**先記招式名稱；盤面還不會出現。
4. 倒數結束，方塊一欄一欄**從上方落下**，對戰開始。
5. 開始倒數後，電腦畫面會自動切換成**直播畫面**：對戰場景、雙方血條與集氣、雙方招式表（盤面上拼得出的招式會亮起），以及方塊盤（左方的招式字染藍、右方染紅）。對戰結束顯示勝方，回到選角後自動切回房號和 QR Code。

### 和電腦對戰

預設是雙人對戰。房間裡只有你一人、還在等對手時，選角畫面上方可以點「**簡單／普通／困難**」改成和電腦對戰：

- 電腦會隨機挑一個角色（可以按「換角色」重抽），你按確定送出後就開始倒數。
- 難度決定電腦集氣滿後多久出招，以及會不會看血量補血：簡單 4.5～8 秒、隨便出招；普通 2.5～5 秒；困難 1.3～2.8 秒。
- 按「等真人」改回等待玩家。還在選角時如果有人掃碼進房，會自動取代電腦，改成雙人對戰。
- 開戰後房間就不再讓其他人加入；你離開房間，電腦也一起退場。

### 使用 ngrok（建議）

```bash
npm start            # 終端機 1
ngrok http 3000      # 終端機 2
```

伺服器會自動讀取本機 ngrok 的 API（`http://127.0.0.1:4040`），找到轉到 3000 的通道後，**電腦畫面上的 QR Code 會自動換成 ngrok 的 https 網址**，不用重新整理。ngrok 本身提供合法憑證，所以手機不會跳憑證警告，麥克風可以直接使用，手機也不需要和電腦連同一個網路。

- 免費版 ngrok 第一次開啟時會顯示一個提示頁，按「Visit Site」即可。
- 也可以手動指定公開網址：`PUBLIC_URL=https://xxxx.ngrok-free.app npm start`

### 不用 ngrok：區網直連

手機和電腦連同一個 Wi‑Fi，QR Code 會指向 `https://電腦IP:3443`。這是自簽憑證，第一次連線會跳出警告（手機要在 HTTPS 下才能用麥克風）：

- Android Chrome：「進階」→「繼續前往」
- iPhone Safari：「顯示詳細資訊」→「造訪此網站」

> 電腦如果有多張網卡、QR Code 上的 IP 不對，可以自己指定：`HOST_IP=192.168.1.20 npm start`
> 連接埠可用 `PORT`（預設 3000）和 `HTTPS_PORT`（預設 3443）調整，記得讓防火牆放行。

### 語音辨識需求

使用瀏覽器內建的 Web Speech API（繁體中文 `zh-TW`）：

| 裝置 | 需求 |
| --- | --- |
| Android | Chrome，**手機要能上網**（辨識由 Google 語音服務處理） |
| iPhone | Safari 14.5 以上，並在設定中開啟 Siri／聽寫 |

> 收音在你按下「確定選擇」時開始（iPhone 的 Safari 只允許在點擊時開始收音），之後**一直開著、不提供關閉**：有些手機把收音關掉再打開就收不到聲音，所以遊戲中不會停止收音，對戰結束、回到選角或離開房間也一樣。辨識中斷時會自動重開；萬一 iOS 不允許自動重開，上方文字列會出現「點一下畫面繼續」，在畫面任何地方點一下即可。

不能用麥克風時，可以在「招式表」裡開啟**手動點選方塊出招**當作備援：依序點選相連的字，再點一次最後一格出招。

### 收音降噪

吵雜環境下，收音會經過一條降噪管線再交給語音辨識（一律開啟；切換開關會重開收音，所以不提供開關）：

1. 瀏覽器內建的噪音抑制、回音消除、自動增益
2. 高通 90Hz：濾掉冷氣、風切等低頻轟隆聲

刻意不做噪音閘、壓縮等重處理，因為那些會切掉字頭、壓扁人聲，反而讓辨識變差。

這條管線需要瀏覽器支援把處理過的音訊交給語音辨識（`recognition.start(audioTrack)`）。新版 Chrome 支援，第一次收音時會自動偵測；不支援的瀏覽器（例如 iPhone Safari）會自動退回系統預設收音，系統仍會做基本的噪音抑制。

語音比對只認得自己角色的招式，旁人或對手念的其他字不會誤觸發（雙方選同一個角色時例外）。

## 玩法

| 操作 | 說明 |
| --- | --- |
| 🎤 持續收音 | 按下「確定選擇」後就一直收音，沒有麥克風按鈕；集氣滿了直接念出招式名稱即可 |
| ⚡ 集氣條 | 控制列右邊的大集氣條顯示自己的集氣百分比，滿了會變金色閃爍「集氣滿！念出招式」（上方人物血條下也有雙方的小集氣條） |
| 📜 招式表 | 列出你的全部招式。同一顆按鈕再按一次就關閉 |
| 🎨 招式顏色 | 每個招式都有專屬顏色，你的招式裡的**每一個字**都會染上該招式的顏色（同一個字出現在好幾招時會分成多色），招式表上有對應的色點。只標你自己的招式，所以兩支手機的字和位置一樣，顏色各自不同 |
| 🚪 離開房間 | 選角畫面右上角、招式表底部、結算畫面都有。對戰中離開會判定落敗 |
| ✨ 閃爍提示 | 集氣滿了 3 秒還沒出招，盤面上會有一組你的招式方塊閃爍（只在你的手機上） |
| 念「重置」 | 找不到招式時重新洗牌，**每人每場 1 次** |

- 招式名稱的字只要**上下左右相連**就算數，不必是一直線，可以任意轉彎（L 形、之字形都可以），但同一格不能重複用。如果想讓斜角也算相連，用 `DIAGONAL=1 npm start` 啟動。
- 只能念**自己角色**的招式。念對以後方塊會消除、上面的方塊往下掉，再從頂端補上新的字。
- **風化**：每個方塊出現時隨機有 3～5 回合的壽命（任一方出一次招算一回合），一直沒被用到就會碎裂消失，讓盤面底部不會卡著湊不成招式的字。剩最後一回合的方塊會褪色並出現裂痕。壽命範圍可以調整 `server/board.js` 的 `LIFE_MIN`、`LIFE_MAX`。
- 語音比對用拼音、不分聲調，逐字算相似分數，只要夠接近自己的某個招式就算數：
  - 同音字、簡體字都算（「玉劍」→ 御劍、「万剑归宗」→ 萬劍歸宗）
  - 台灣口音：zh/z、ch/c、sh/s、n/l、in/ing、en/eng、fu/hu 不分
  - 讀音差一點的字給部分分數（「天光戰器」→ 天罡戰氣）
  - 句子裡多出的字會略過（「我要用萬劍歸宗」），四字招式聽錯或漏掉一個字也行（「萬劍宗」）
  - 數字會轉成國字（「5氣朝元」→ 五氣朝元）
  - 好幾個招式聽起來都像時，優先選盤面上找得到的那一個
  - 「重置」只有完全同音才算，避免講「總之」之類的詞時誤觸

### 盤面保證有招式可念

伺服器每次補字以後都會檢查盤面，確保**雙方各自至少有 2 個自己的招式**可以念（開局時是 3 個）。如果不夠，就把缺少的招式「種」進盤面：優先種在剛掉下來的新格子，並避開其他現存招式的路徑，讓已經看到的字盡量不變。單元測試會連續消除 2000 次來驗證這個保證。

招式越長威力越大（2 字 ≈ 1.0、3 字 ≈ 1.35、4 字 ≈ 1.6 倍），因為越長的招式在盤面上越難找。一般招式約造成對手 8%～15% 氣血的傷害，**單次傷害最多 25%**，就算暴擊加上增益也不會一兩招就結束。

### 平衡調校

`npm run balance` 會用真實的對戰邏輯讓機器人兩兩對打。機器人集氣滿後要花 1.5～4.5 秒「找字」才出招，左右各打一半。目前的數值下，各角色總勝率都在 **47%～54%**，任兩個角色對戰的勝率都在 41%～62% 之間。平均一場約 100 秒，勝方大約要出 11 招。想讓節奏更快或更慢，可以調整 `server/game.js` 裡的 `SKILL_BASE`（招式傷害）和 `GAUGE_BASE`（集氣速度），再重跑確認。

## 專案結構

```
server/
  index.js    HTTP + HTTPS 伺服器、Socket.IO、房間管理、QR Code
  room.js     房間：進房順序、選角、倒數、斷線重連（30 秒內）、再戰、電腦對手
  bot.js      電腦對手的出招邏輯（三種難度）
  game.js     即時戰鬥邏輯（伺服器權威）：集氣、傷害公式、增減益、持續傷害
  board.js    文字方塊：相連路徑搜尋、掉落補字、保證有招式的演算法
  speech.js   語音結果比對（拼音、同音字、口音容錯）
public/
  index.html  電腦端首頁（房號 + QR Code）
  play.html   手機端
  shared/characters.js  角色與招式資料（前後端共用）
  js/sprites.js   人物繪製與動作（有立繪圖就用圖，否則用 Canvas 畫 Q 版人物）
  js/scene.js     對戰場景：背景、角色、傷害數字
  js/fx.js        招式特效：粒子系統、閃電、劍氣、法陣，以及 30 招各自的特效
  img/            立繪、特效圖、背景（由 scripts/art.py 產生）
  js/boardview.js 方塊棋盤動畫
  js/voice.js     Web Speech API 包裝與收音降噪管線
scripts/balance.js  平衡模擬
scripts/art.py      把 art/raw/ 的原始圖去背、裁切並產生 public/img/manifest.json
art/README.md       用 Gemini 生成角色立繪與特效圖的提示詞
test/               單元測試（npm test）
```

## 修改提示詞（學生改造任務）

把下面的提示詞貼給 AI 程式助手（例如 Claude Code），讓它幫你改這個遊戲。`＿＿` 的地方換成你自己的想法。

### 寫好提示詞的 4 個訣竅

1. **說效果，不要只說「改好玩」**：想像玩家會看到什麼、感覺到什麼。
2. **給數字**：多快、多痛、幾秒、多少機率。數字講清楚，AI 才不會亂猜。
3. **指出位置**：知道要改哪個檔案就寫出來；不知道就請 AI「先找出相關的程式碼再改」。
4. **要求驗收**：請 AI「改完跑 `npm test`，並說明改了哪些檔案」。改數值的話加上「跑 `npm run balance` 給我看勝率」。

| ❌ 太模糊 | ✅ 講清楚 |
| --- | --- |
| 請加大攻擊力 | 請讓一場對戰大約 60 秒結束，但單招傷害不要超過對手血量的 35%，改完跑 `npm run balance` 給我看結果 |

> 建議一次只改一件事，改完自己玩一場確認，再用 git commit 存檔。改壞了可以用 `git checkout .` 還原。

### ⭐ 入門：改數值、改文字

**1. 加快節奏**
```
請把對戰節奏加快，讓一場大約 60 秒結束（現在約 100 秒）。
主要調整 server/game.js 的 SKILL_BASE（招式傷害）和 GAUGE_BASE（集氣速度），
單次傷害上限 HIT_CAP 不要超過 35%，避免兩招就結束。
改完跑 npm run balance，把平均對戰時間和各角色勝率給我看。
```

**2. 拚眼力的困難模式**
```
請在招式表裡加一個「困難模式」開關：打開後盤面方塊不顯示招式顏色，
只能靠眼力找字；關掉就恢復顏色。顏色是在 public/js/play.js 的 applyCharColors() 套用的。
這個開關只影響自己的手機，重新整理後要記得上次的設定。
```

**3. 武俠風結算台詞**
```
請把結算畫面改得更有趣：勝利時隨機顯示一句武俠風台詞（例如「承讓了！」），

結算畫面在 public/js/play.js 的 showResult()。
```

**4. 調整規則**
```
請把開戰前倒數改成 5 秒（server/room.js 的 COUNTDOWN_MS），
每人每場的重置次數改成 2 次（server/game.js 的 C.RESETS），
畫面和 README 上提到秒數、次數的文字也要一起改。
```

```
請加入場地事件：開戰後每 30 秒隨機發生一個事件，持續 10 秒，畫面上方要公告，例如：
「雷雨」名稱有「雷」字的招式傷害 +30%、「月圓」補血量加倍、「狂風」雙方集氣速度 +30%。
事件由伺服器決定，兩支手機同步顯示。至少設計 4 種事件。
```

**12. 喊招音效**
```
請用 Web Audio API 自己合成音效（不要用外部音檔）：出招、受擊、暴擊、集氣滿、勝利、落敗各一種，
並在招式表加一個「音效」開關。注意音效不能太大聲，以免干擾麥克風辨識招式。
```

**13. 語音嘲諷**
```
請加入嘲諷：念「來啊」或「哈哈哈」時，自己的角色做出嘲諷動作，頭上冒出對話框，對手手機也看得到。
不消耗集氣，每 5 秒最多一次，而且要完全同音才算（參考 server/speech.js 裡「重置」的嚴格比對），
避免平常講話誤觸。
```

**14. 戰績排行榜**
```
請在電腦首頁的 QR Code 旁邊顯示這個房間的戰績：每個角色的勝場數、最快 KO 秒數、單場最多出招次數。
資料存在伺服器記憶體就好，伺服器重開後清空。
```

### 課堂玩法建議

- **分組改造**：每組挑一個任務，改完互相對戰，最後票選「最好玩的改動」。
- **平衡挑戰**：改完數值後跑 `npm run balance`，讓每個角色的勝率都在 45%～55% 的組別加分。這可以帶出「遊戲平衡」的概念：只加強一個角色很容易，讓大家都有機會贏很難。
- **先猜再看**：請 AI 改之前先說明打算改哪些檔案、為什麼，學生先猜猜看，再對照 AI 的做法。
